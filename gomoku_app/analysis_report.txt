一、设备发现
================================================================================

流程:
  设备A/B同时启动
    → WebSocketServer.bind(anyIPv4, 0)    // 随机端口
    → mDNS: RawDatagramSocket 绑定 55555
    → 加入组播组 239.255.0.1
    → 每 5 秒广播 announce(device_id, name, port, platform)
    → 收到非自身 announce → 添加到在线列表
    → 每 5 秒清理 10 秒未更新的设备

[安全]   忽略自身 announcement (通过 device_id 匹配)       ✓
[正确]   广播间隔 5s, 过期 10s, 清理间隔 5s               ✓

潜在问题:
  ├── UDP 组播依赖路由器: 企业/公共 WiFi 可能隔离
  │    → 两台手机永远看不到对方
  │    → UI 显示 "正在搜索..." 无超时提示
  │    → 建议: 添加 "网络检查" 功能或提示
  │
  └── 过期清除有 10-15s 延迟
      → 关闭 WiFi 后设备仍可见
      → 用户可能点击离线设备的 "邀请" 按钮
      → 此时 connectToPeer 会因 TCP 超时而卡住（见问题2）

🔴 问题1: 邀请方显示 "对手" 而非真实名称
--------------------------------------------------------------------------------

文件:   lobby_screen.dart:119-121
方法:   _navigateToGame()
代码:   final opponentName =
            ref.read(invitationStateProvider.notifier).fromPeerName ?? '对手';

根因:
  InvitationNotifier 区分两个方向:
    - fromPeerId / fromPeerName: receiveInvite() 设置 (仅接收方有)
    - toPeerId   / toPeerName:   sendInvite() 设置 (仅发起方有)

  发起方路径: sendInvite() → toPeerName 有值, fromPeerName 为 null
  接收方路径: receiveInvite() → fromPeerName 有值

  _navigateToGame() 只检查 fromPeerName, 发起方永远走到 ?? '对手'

影响:
  - 发起方进入游戏后, AppBar 标题显示 "对手"
  - 局内 GameInfoBar 中 opponentName 也显示 "对手"
  - 接收方显示正确名称

修复方案:
  final opponentName =
      ref.read(invitationStateProvider.notifier).fromPeerName ??
      ref.read(invitationStateProvider.notifier).toPeerName ??
      '对手';

🟡 问题2: WebSocket 连接无超时
--------------------------------------------------------------------------------

文件:   websocket_client.dart:21
代码:   _webSocket = await WebSocket.connect('ws://$host:$port');

风险:
  - Dart/Flutter 的 WebSocket.connect 默认使用 Socket.connect
  - 系统 TCP 超时通常为 20-120 秒 (平台相关)
  - 当对端离线(但仍显示在列表)时, 用户点击邀请会等待 20s+
  - 期间无任何进度提示, 只有 "正在邀请 XXX..." 转圈

修复建议:
  _webSocket = await WebSocket.connect('ws://$host:$port')
      .timeout(const Duration(seconds: 10));
  // 在 catch 中处理 TimeoutException

三、游戏对局
================================================================================

正常流程:

  黑方(发起方)                        白方(接收方)
    │                                   │
    ├─ isMyTurn = true                   ├─ isMyTurn = false
    │                                   │
    ├─ 点击交叉点                         │
    ├─ isValidMove(row, col)             │
    ├─ placeStone(row, col)              │
    │   → engine 更新                    │
    │   → state 更新 (含移步记录)         │
    ├─ 发送 game_move(row, col, stone)   │
    │   stone: 1=黑, 2=白               │
    ├─ 检查 status                       │
    │   if won/draw → 发送 game_over     │
    │                                   │
    │                         game_move →
    │                                   ├─ receiveMove(row, col, stone)
    │                                   │   → engine.placeStone
    │                                   │   → state 更新
    │                                   ├─ isMyTurn = true
    │                                   │
    │        ← game_move (对方落子)      │
    ├─ receiveMove(row, col, stone)      ├─ 点击落子...
    │                                   │
    │           ...循环...               │

正确性验证:

  [消息协议] game_move.payload.stone: 1=黑, 2=白
    - 发送: gameState.myStone == Stone.black ? 1 : 2
    - 接收: payload['stone'] == 1 ? Stone.black : Stone.white
    - Stone.empty=0, black=1, white=2    ✓

  [轮次控制] isMyTurn = (myStone == currentTurn)
    - 每次落子后引擎切换 currentTurn     ✓
    - 非自己回合时 onTap 提前 return     ✓

  [引擎判定] _checkWin 四方向 O(1) 扫描
    - 方向: (0,1)水平, (1,0)垂直, (1,1)正斜, (1,-1)反斜
    - 从落子点向两边各数 <winStreak(5) 步
    - 判定准确                           ✓

  [平局检测] _moveCount >= 15*15 = 225  ✓

  [坐标计算] (修复后) 使用 RenderBox 尺寸
    - GestureDetector 的 localPosition    ✓
    - 与 CustomPainter 使用同一尺寸源    ✓

四、游戏结束
================================================================================

场景A: 正常胜利/平局

  落子方:
    placeStone() 返回 true
    → status = won (或 draw)
    → 发送 game_move → 发送 game_over(win/draw)

  对手:
    收到 game_move → receiveMove → status = lost (或 draw)
    收到 game_over → 'win'/'draw' 忽略 (状态已更新)

   ✅ 此路径正常

场景B: 强行退出

  退出方:
    点击返回 → _showExitConfirm
    → 用户确认 → 发送 game_over(quit)
    → resetGame → Navigator.pop

  对手:
    收到 game_over(quit) → endGame → disconnected
    → GameOverDialog 显示 "连接断开"

   ✅ 此路径正常

场景C: 连接断开

  服务端检测:
    WebSocket.onDone/onError
    → _disconnectController.add
    → connection_manager 监听
    → 发送 connection_lost

  客户端检测:
    WebSocket.onDone/onError
    → _connectionStateController.add(false)
    → connection_manager 监听
    → 发送 connection_lost

  lobby 处理 connection_lost:
    if (status == playing) → endGame
    else → SnackBar
    → reset invitation

   ✅ 此路径正常

场景D: 断线重连

  无重连机制:
    → 直接结束游戏, 显示 "连接断开"
    → 无重试/重连

  可接受 (休闲游戏), 但弱网环境体验差

🔴 问题6: "再来一局" 按钮无效
--------------------------------------------------------------------------------

文件:   game_screen.dart:120-122
代码:   onRematch: () {
          ref.read(gameStateProvider.notifier).resetGame();
          // TODO: send rematch request
        },

问题:
  - 点击后只 resetGame() → 重置本地引擎
  - 不发送任何消息给对手
  - 对手状态不变 (仍显示游戏结束)
  - 双方状态立刻不同步

影响:
  - 本地: 棋盘清空, status = waiting, myStone = null
  - 对手: 仍然是游戏结束界面
  - 此时如果对手点击任何按钮或落子, 状态会错乱

建议方案A: 实现完整重开协议
  1. 发送 rematch_request 给对方
  2. 对方收到后弹窗询问
  3. 双方都同意后重置游戏引擎
  4. 决定谁执黑 (交替或原样)

建议方案B: 暂时隐藏按钮
  - 注释掉 onRematch, 或把按钮设 disabled
  - 文本改为 "敬请期待"

--------------------------------------------------------------------------------
🟡 问题7: 退出游戏后 WebSocket 未关闭
--------------------------------------------------------------------------------

涉及路径:

  路径1: _showExitConfirm → 发送 game_over(quit) → resetGame → pop
  路径2: GameOverDialog.onQuit → resetGame → pop
  路径3: 系统返回键 (PopScope)

  以上均未调用 _connectionManager.disconnect()

影响:
  - 旧 WebSocket 连接持续打开
  - 残留的 game_move 消息可能被 lobby 处理
  - 在对方也退出/断线前, 连接一直存在

特别风险: resetGame 后残留 game_move 抵达
  receiveMove → engine.placeStone(引擎已重置!)
  → 石头被放置在空棋盘上
  → 状态被设置为 playing
  → 出现 "幽灵对局"

实际上此风险较低 (消息在 game_over 前已处理完毕),
但仍应在退出时主动 disconnect。

--------------------------------------------------------------------------------
🟡 问题9: receiveMove 不检查游戏状态
--------------------------------------------------------------------------------

文件:   game_providers.dart:102-138
代码:   void receiveMove(int row, int col, Stone stone) {
          _engine.placeStone(row, col, stone);  // 可能返回 null
          if (_engine.isGameOver) { ... }       // 继续执行
        }

问题:
  - placeStone 返回 null 时 (游戏已结束/无效走子)
  - receiveMove 不检查返回值, 继续使用 engine 状态
  - 如果引擎已 reset, 会错误地放置棋子

修复建议: 添加返回值检查
  final result = _engine.placeStone(row, col, stone);
  if (result == null) return;  // 游戏已结束, 忽略
